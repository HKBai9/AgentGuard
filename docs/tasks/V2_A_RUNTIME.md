日期：2026-10-21；功能补齐更新：2026-10-22。核心运行时之后，本轮已接入实际宿主恢复、风险引用、受控查询/审计与联合应用入口，见 [功能补齐记录](../v2/FEATURE_COMPLETION.md)。比赛演示与真实云端实验按用户要求暂缓；此前测试记录保留在 [集成验收报告](../v2/INTEGRATION_REVIEW_2026-10-22.md)。下面任务卡继续作为验收要求。

你负责让权限与数据边界真正生效。即使 Guard 误判、超时，或者返回“一律允许”，程序仍须守住宿主已经明确给出的限制。B 负责模型理解与证据选择，你不必等待模型效果调好才开始。

先读 [总任务书](../V2_TWO_PERSON_PLAN.md) 和 [共享接口约定](V2_SHARED_CONTRACT.md)。架构底线见 [实施计划](../V2_IMPLEMENTATION_PLAN.md)。

## 1. 你的文件与交付范围

你拥有 `agentguard/v2/` 下的公共类型/Protocol、runtime/bootstrap/registry、policy 的 validator/engine、state、execution、recovery 的 checkpoints、Python/MCP 工具适配和 gateway。测试写入 `tests/v2/runtime/`、`contracts/`、`integration/`。

公共依赖、包发现、锁定文件、根测试配置和集成分支由你维护。B 的 policy/compiler、review、host/framework、UI、benchmarks 不由你直接重写。嵌套路径和文档负责人以总任务书的表为准。

你最后交付：能安装的 v2 内核、SDK 与网关、可核验的状态/来源记录、故障和竞争测试，以及 B 可以接入的统一 RuntimePort。

## 2. 第一轮立即执行

1. 在独立分支/工作目录记录当前旧版提交号、Python/依赖环境和现有测试结果；旧功能先保留。
2. 创建 v2 公共模型和 Protocol，落实契约版本 `0.1`。第一批优先 PolicyCandidate、ToolCall、ArtifactVersion、ContextMaterial、ReviewDecision、Permit、Receipt。
3. 在自己的测试目录写 FakeReviewer 和固定 PolicyGenerator：分别模拟允许、拒绝、脱敏、超时、畸形返回。模拟件不能进入正式默认配置。
4. 用本地假工具做一条最短路径：调用有 ID → 执行许可被领取 → 工具返回被隔离 → 模拟审查 → 释放获准版本。
5. 把小版本公共类型交给 B；随后继续数据库和约束测试，不等 B 接真实模型。

第一轮结束必须能回答：“调用是否真正执行、原文是否释放、同一个调用是否重复执行？”先不要搭完整控制台。

## 3. 分任务卡

### A01｜公共契约、运行外壳与旧版基线（S0）

**实施：**

- 将共享契约落实到 `contracts.py`、`ports.py`；导出可离线使用的 JSON Schema，校验额外字段/未知枚举/必填缺失。
- `runtime.py` 提供 RuntimePort 外壳；`bootstrap.py` 注入 PolicyGenerator、GuardService 和状态组件，避免相互导入实现。
- 定义一致的 ID、事件信封、错误码、摘要和参数序列化；不要让两个模块各算一套绑定值。
- 增加 `tools/v2/verify_runtime.ps1` 的初始入口，保留旧版测试结果作为基线。

**可用替代品：**自己的内联最小 fixtures 与 FakeReviewer；不等待 B 完整样本集。

**验收：**A/B 均能解析相同请求和判定；未知版本、错误关联 ID、缺字段失败；仅导入公共类型无需云端密钥或启动服务。

**交给 B：**公共模型小提交、Schema、最小合法/非法示例、导入路径。**完成记录：**测试命令、结果和提交号。

### A02｜工具登记、有限策略校验与版本（S1）

**实施：**

- `registry.py` 登记宿主确认的 tool_id、版本、效果、资源/目的地参数位置与输出类型。
- `policy/validator.py` 校验 B 的候选格式、资源引用、宿主上限；`engine.py` 执行有限规则。
- 先以固定候选测试，再接 B 的真实生成器。实现版本库，区分初始候选、收紧、扩张和无法判断的变化。
- 规范化资源目录和接收端，拒绝未知工具/未知效果；远程工具描述不能自行获得新权限。

**前置：**A01。**不依赖：**B 的提示词质量。

**验收：**人工权限矩阵通过；本地报告任务没有 SEND；明确发送任务只允许指定假接收器；候选越过宿主边界或无法证明安全收紧时不自动生效。

**交给 B：**validator 的确定错误码和策略差异数据，便于 B 区分“模型生成错格式”与“任务缺少授权”。

### A03｜隔离存储、最小许可与内容释放（S1）

**实施：**

- `state/store.py` 建立 SQLite 事件、对象元数据、许可和调用状态；事务后才报告状态成功。
- `state/artifacts.py` 保存原始内容的不可变版本，包含正常结果、错误正文、stderr 和结构化返回。
- `execution/permits.py` 先实现最小的原子领取与 `(session_id, call_id)` 唯一执行；真实副作用试验前必须有此能力。
- 在 Runtime 中先存原文，再生成 ContextMaterial 调 B；合法 ALLOW 才能释放，REDACT 按预登记变换生成新版本，BLOCK 保持隔离。
- 校验审查对象、版本、证据范围和变换 ID；原文禁止从异常、回调、日志或直接 return 泄漏到主 Agent。

**前置：**A01—A02。**替代品：**FakeReviewer 覆盖所有处理分支；先用假工具。

**验收：**B 的实际 Reviewer 接入后能跑通正常、注入和字段脱敏样本；超时、格式错、伪造引用均不释放；重复回调不能再次释放错误版本。

**S1 联调交付：**真实 A + 真实 B 的最小纵向闭环，不要求 UI 完成。

### A04｜完整许可、批次与执行故障（S2）

**实施：**

- 把参数摘要、工具版本、对象版本、策略/上下文/相关安全版本及 TTL 绑定进 Permit。
- 在同一事务中完成重验与领取；即使同一调用因重试拿到两个许可，也只能调度一次。
- 为写共享资源、限额和预算设计原子预留或串行执行；不要持有数据库事务等待云端模型/远程工具。
- `executor.py` 区分成功、已知失败和 UNKNOWN；领取后进程崩溃、外发后异常等不能自动重试非幂等动作。
- `batch.py` 为每个调用绑定 session/turn/call/context，独立收集结果和审查状态；下一轮通过屏障构建输入。
- 不能用可变文件路径代替已批准的内容版本；相关安全状态改变时重新审批。

**前置：**A03；完整来源版本与 A05 一起联调。

**验收：**并发抢同一许可至多调用一次；两许可同一 call_id 仍至多一次；替换参数/内容/工具/策略后旧许可失败；20 个乱序调用不串号；副作用后异常标 UNKNOWN，接收器不因自动重试收到第二次请求。

**交给 B：**可展示的 Permit/Receipt 事件，以及成功/失败/未知的稳定原因码。

### A05｜来源标签、模型输入与最终输出门禁（S2）

**实施：**

- `state/lineage.py` 维护完整性、保密性和用途约束；区分 exact/possible 边。
- 实现 `prepare_model_turn`/`record_model_output`：记录真正送入模型的快照，并让模型输出保守继承输入限制。
- 产生给 B 的 ContextMaterial：必保留的权限/标签/未决风险独立于历史文本；关系相关的正文可供 B 选择。
- 对 ArtifactRef 校验会话、版本、工具、用途和目的地，不允许跨会话解引用。
- 实现 `finalize`：把最终文本先当成待审对象，审查与独立检查通过后才对外释放；用户界面不能先展示流式原文。
- 字段级预批准脱敏可以移除对应字段限制；文档级限制和摘要派生限制不随意清除。

**前置：**A03；与 B04/B05 对接。**替代品：**固定 ContextMaterial 消费器和假宿主模型输入。

**验收：**10/30/60 步轨迹限制不丢；第 3 步受限资料在第 30 步摘要发送仍受约束；AlwaysAllowReviewer 无法突破宿主预置限制；最终输出门禁和可信模型目的地检查可独立失败。

### A06｜Python SDK、HTTP/MCP 与安装包（S3）

**实施：**

- `adapters/python.py` 提供同步/异步工具包装，复用现有 SDK 的签名绑定思路；不复用会在审查前直接返回原值的路径。
- `gateway/app.py` 实现共享契约的宿主写接口和 UI 只读接口；业务拒绝、冲突、格式错和服务故障分开。
- `adapters/mcp.py` 使用锁定版本的官方 SDK，实现明确支持的工具请求/结果边界；未覆盖能力明确关闭。
- 首批接入读文档、写报告、发送报告、只读查询四类假工具；验证不同接入方式使用同一策略内核。
- 补齐 v2 子包与包内模板/Schema；包发现仅包含 agentguard 及其子包；v2 发布环境采用 Python 3.12。
- 提供网关部署边界说明：后端凭据与网络/文件访问须受控，否则只能称受约束的 SDK 集成。

**前置：**核心闭环可用；Schema 外壳可早做，正式路由晚接。

**验收：**Python/HTTP/MCP 合同测试一致；一个未支持协议面确实拒绝；普通 UI 请求无法读取隔离原文；源码目录外装 wheel 后资源加载和调用通过。

**交给 B：**真实 HTTP 服务、OpenAPI/公共 Schema、启动参数与脱敏查询样例，不要求 B 直连数据库。

### A07｜影响范围计算与恢复状态机（S3）

**实施：**

- `recovery/checkpoints.py` 从风险对象计算影响范围，保留确有独立来源的结果；可能依赖不能冒充无依赖。
- 撤销未领取许可，产生 RecoveryPlan，列出受影响对象、可重建输入、必需宿主重置项和不可撤销效果。
- 恢复期间阻止旧上下文发起新执行；只有对应 RecoveryAck 满足所需钩子后才切换新的安全上下文。
- 给控制台输出恢复计划、实际 Ack、未完成项和 UNKNOWN；不要把“已生成计划”显示为“已恢复”。

**前置：**A05 来源关系；B05 提供宿主重置实现。

**验收：**风险在晚期发现时撤销影响范围内待执行动作；正常独立结果可继续；Ack 缺失/错误时不能恢复；已发送内容不能在界面伪装成撤回。

### A08｜硬约束总验收与交付修复（S4）

**实施：**

- 在 `tests/v2/integration/` 建真实组件联调入口，覆盖 A/B 契约、故障、并发、安装与恢复。
- 给 B 的评测提供同一 Runtime 的开关与事件接口，禁止为了漂亮分数另建隐藏的“演示执行器”。
- 对延迟与锁竞争做测量后再优化；修复不能改变失败保持隔离、单次领取和版本校验语义。
- 统一更新 README、能力边界和公共依赖；协助 B 从干净环境跑五个比赛场景。

**验收：**总任务书的全部程序底线有断言；旧版对照可在记录的环境运行；API 模型效果与程序约束分别出报告；不存在“当前已实现”却无测试/演示证据的声明。
