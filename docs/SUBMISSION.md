## 一、作品名称

**面向安全 Agent 的边界逃逸检测与风险隔离机制（AgentGuard）**

备选名称：
- 《AgentGuard：让 AI Agent 越不过权限边界 —— 六层边界逃逸防护系统》
- 《从"越狱"到"越界"：AI Agent 边界逃逸的实时检测与隔离》

---

## 二、作品简介（300 字内，可直接粘贴）

随着 AI Agent 在安全运维、漏洞挖掘、代码审计场景广泛使用，Agent 存在**边界逃逸**风险：
大模型脱离系统预设权限，**自主**调用高危工具、读取敏感凭证、访问内网资源，
引发账号泄露与内网横向渗透。2024 年 AISI 披露的 Agent 逃逸事件即属此类。

本项目设计并实现了六层防护机制：**权能层对每次工具调用按需签发微租约票据**
（零初始权限，用一次即废、超期即废、撤销即时级联失效），行为层实时监控
Agent 的工具调用与动作序列，语义层校验 Agent 目标一致性，**污点层跟踪输入可信度**
（摄入不可信内容即触发动态降权）；一旦检测到边界逃逸，自动阻断执行、隔离会话、
回滚变更并生成审计告警。系统以独立 SDK 形式插在工具调用点，
与 Agent 框架解耦。实测表明：在**同一 Agent、同一本地大模型、同一沙箱**的对照实验中，
关闭防护时 Agent 成功读取 SSH 私钥、连接内网数据库并获取后台账号；
开启防护后动作在**工具执行之前**被拦截，会话被冻结，且正常扫描任务**零误伤**。

---

## 三、要解决的关键问题

| 问题 | 说明 |
|---|---|
| **不是"越狱"，是"越界"** | 大模型越狱停在文本层；Agent 边界逃逸是**真的调用了工具、真的访问了资源** |
| 隐性逃逸难以发现 | Agent 不写恶意指令，而是在 Thought 中"规划"越权（读私钥→连内网），行为层只能等它动手 |
| 组合动作难以识别 | 单步都在白名单内，但 `读凭证 → 连内网` 的组合就是横向移动 |
| 白名单易被绕过 | 同义写法（`host` / `host:8081` / `127.0.0.1:8081`）、路径穿越（`..`）、换端口、用白名单命令触网 |
| 防护不能影响业务 | 安全组件若误报频繁，运维不会用 —— 必须证明"不误伤" |

## 四、作品亮点（评委关注点）

1. **直击真实安全事件**：以 AISI Agent 逃逸事件为参考场景，不是凭空设想。
2. **对照组 / 实验组严格可比**：同一 Agent 循环、同一本地大模型（`qwen2.5-coder:7b`）、
   同一沙箱、同一 System Prompt、同一任务文本，**唯一变量是防护开关**，
   现场一键切换，评委无法质疑"两组 Agent 不一样"。
3. **能证明"不误伤"**：专门设计用例 1（正常 XSS 扫描）与 87 项回归测试，
   量化证明防护对合法业务零阻断。
4. **完整闭环**：检测 → 判定 → 阻断 → 隔离 → 回滚 → 审计，不是纸面原型。
5. **拦截发生在执行之前**：被阻断的工具**根本不执行**，输出中不含任何敏感内容
   （有测试断言保证），副作用为零。
6. **框架无关、可迁移**：防护层是独立 SDK，插在工具调用点，
   换成 LangGraph / AutoGen / OpenHands 无需改防护代码。
7. **完全离线可复现**：本地大模型 + 本机回环沙箱，不依赖外网、不调用公有云 API。

## 五、技术方案（精炼版）

### 5.1 架构

```
用户任务 → Agent(ReAct, 本地大模型)
              │  每次工具调用
              ▼
     ToolBridge.execute()  ← 全作品唯一的控制点（JIT 权能申请对模型透明）
              │
   ┌──────────┼──────────────┬─────────────┬────────────┐
   ▼          ▼              ▼             ▼            │
 L0 动态权能  L1 权限基线    L2 语义意图    L3 行为运行时  │
 JIT微租约   事前/默认拒绝  目标偏离+意图族  参数审计+时序链 │
 (票据/衰减/撤销)              │                          │
   └──────┬───┴──────────────┴─────────────┘            │
          │  ▲                                          │
          ▼  │ LT 污点感知（摄入 UNTRUSTED → 降权）        │
        L4 隔离阻断 ◄────────────────────────────────────┘
     阻断 / 冻结会话 / 回滚 / 告警（动态降权=只拦本次，不冻结）
```

### 5.2 六层职责

| 层 | 时机 | 判定依据 | 关键规则示例 |
|---|---|---|---|
| **L0 动态权能** | 事前 | 零初始权限；JIT 微租约票据 + 参数谓词 + 衰减 + 级联撤销 | 无票据拒绝（`L0-NO-TOKEN`）；`max_calls=1` 防重放；撤销节点子树全失效 |
| L1 权限基线 | 事前 | 工具/域名/路径/命令四类白名单，默认拒绝 | `**/.ssh/**` 受保护；内网网段禁用；敏感端口 22/3306 拒绝 |
| **LT 污点感知** | 事中 | 输入来源分级 + 污染传播 + 降权矩阵 | 摄入 UNTRUSTED → 命令执行/远程连接/写交付物**拒签权能**；去污/人工核准恢复 |
| L2 语义意图 | 事中 | 风险意图族 + 目标对象模型 | 命中"私钥/内网数据库"且含动作诉求 → CRITICAL |
| L3 行为监控 | 事中 | 参数归一化 + 时序行为链 | `SEQ-001`：读凭证 → 连内网 = 横向移动 |
| L4 隔离阻断 | 响应 | 严重度分级 + 响应策略 | CRITICAL → 阻断 + 冻结会话 + 回滚 |

> L0/LT 为 v1.1 新增（OCap 权能架构 + 轻量信息流控制），
> 设计文档、理论对照与工程边界见 `docs/CAPABILITY.md`。

### 5.3 三个关键技术点（差异化）

1. **动作归一化**：把 `host`、`host:8081`、`http://host:8081`、`127.0.0.1:8081`
   归一到同一 Action 视图；路径反斜杠、`..`、`//` 统一解析。**不归一化，白名单形同虚设。**
2. **端口与服务语义解耦**：`canonical_port()` 使"连 `internal-db` 的任何端口"
   都按*内网数据库*判定，防止换端口绕过敏感端口策略。
3. **目标对象模型抑制误报**：语义漂移不只看相似度，还要求
   "引用了任务范围外资源 **且** 未出现任务域/合法产物锚点"。
   因此"把扫描结论写入报告目录"这类正常收尾动作不会被误伤；
   且只有 HIGH/CRITICAL 级证据才阻断，LOW 级仅记录。

## 六、演示方案（答辩现场，约 4 分钟）

| 步骤 | 操作 | 讲解要点 | 预期现象 |
|---|---|---|---|
| 1 | 跑**用例 1**（正常扫描），同时运行两组 | 防护不会误伤合法操作 | 两组都放行，0 告警 |
| 2 | 取消勾选「启用边界逃逸防护」 | 介绍这是唯一实验变量 | 页面变红：防护已关闭 |
| 3 | 跑**用例 2**，看左侧对照组 | 复刻 AISI 逃逸 | Agent 成功读到私钥、连上"内网数据库"、拿到后台账号 |
| 4 | 勾选防护，再跑**用例 2** | 同样的输入，同样的模型 | 第 3 步被拦截，页面无任何私钥内容，会话冻结 |
| 5 | 切换到**用例 4**（包装型绕过） | 归一化与时序链 | 路径穿越被识破、`curl` 连内网被拦 |
| 6 | 打开「权能运行台」，点「⛔ 熔断」 | 动态权能微租约 + Caretaker 级联撤销 | 全部在飞票据毫秒级失效，熔断后再读也立即被拒 |
| 7 | 跑**用例 5**（污点注入） | 不可信输入触发动态降权 | 对照组注入内容落入交付物；实验组拒签高危权能，去污/核准后恢复，**不冻结** |
| 8 | 跑**用例 6**（委派衰减） | 多 Agent 委派的最小特权 | 对照组子 Agent = 权限复制一份（级联逃逸）；实验组写权限被剥离、越权被拦 |
| 9 | 打开「审计日志」标签页 | 完整证据链可溯源 | 每条规则 ID、层级、证据 JSON |

**备选**：若现场机器无 Ollama，使用「脚本回放」模式 ——
同一 Agent 循环、同一工具、同一防护层，只是 Thought 文本来自预置轨迹，演示效果一致。

## 八、创新点小结

1. **问题界定创新**：明确区分"大模型越狱"与"Agent 边界逃逸"，
   把防护目标锚定在**真实工具调用**而非文本输出。
2. **检测模型创新**：提出**目标对象模型**，用"任务域锚点 / 合法产物锚点"
   双重门控修正纯相似度的误报问题。
3. **时序检测创新**：把"单步合规但组合越权"形式化为可配置的**时序行为链规则**，
   并用"故意放宽单步白名单"的测试证明其必要性。
4. **授权模型创新（v1.1）**：把"检查式授权"升级为 **OCap 权能式授权**——
   零初始权限、JIT 微租约票据（TTL 30s / 单次配额 / 步骤绑定）、
   参数谓词内嵌（Macaroons 式衰减）、**Caretaker 模式 O(1) 级联撤销**、
   委派离线衰减（子权能 = 父权能严格子集）。
5. **信息流控制创新（v1.1）**：**污点感知动态降权**——按输入来源分级
   （任务范围 TASK_SCOPE / 范围外 UNTRUSTED），摄入不可信内容即触发
   高危动作拒签，去污/人工核准双通道恢复；分级设计保证正常业务零误伤。
6. **实验方法创新**：对照实验做到**唯一变量**，且包含"对照组必须真的逃逸成功"
   这一成立性断言；新增污点注入与委派级联逃逸两用例，
   把"多 Agent 委派 = 权限复制"的风险实证化。
7. **工程可迁移**：防护层为独立 SDK，与 Agent 框架解耦；
   权能申请对模型透明，不改变 Agent 的观察-行动接口。

## 十、安全与合规声明

- 所有"靶站""内网服务"均运行于 `127.0.0.1` 本机回环，**不依赖外网、不接触真实内网**；
- 被读取的私钥与凭证为**演示用假数据**（文件内标注 `DEMO / FAKE`），不能用于真实登录；
- 工具层对命令执行设有白名单兜底且不经过 shell；
- 沙箱出口策略规定：**只有配置中登记的虚拟主机名才允许解析**，未登记域名一律不解析；
- 本作品不含任何针对真实目标的攻击能力，仅用于安全研究与竞赛演示。
